# Endpoint-агент (этап Э1.5)

Агент на рабочей станции закрывает канал, который не видят ни браузерное
расширение, ни сетевой периметр: **буфер обмена** и **локальные
LLM-приложения** (Claude Desktop, Cursor). Типовой сценарий утечки:
сотрудник копирует договор, клиентскую базу или `.env` и вставляет в
локальное приложение — текст уходит во внешнюю LLM в обход браузера и
egress-proxy (E2E-трафик, который не видит SASE — раздел 4.3 ТЗ).

## Как работает

```
копирование ──▶ агент (poll буфера)
                  │
                  ├─ локальный детект (без сети, общие детекторы ядра)
                  │     └─ чисто → ничего не происходит
                  │
                  ├─ чувствительное → шлюз /v1/check (канал endpoint)
                  │     ├─ mask  → буфер подменяется обезличенным текстом
                  │     └─ block → буфер очищается (оригинал в quarantine)
                  │
                  ├─ шлюз недоступен + чувствительное → fail-closed:
                  │     буфер очищается
                  │
                  └─ ответ LLM с [IIN_1]... → /v1/restore → значения
                        подставляются обратно в буфер
```

Политика и аудит — центральные (на шлюзе): администратор видит канал
`endpoint` в журнале и отчётах, правила настраиваются per-канал
(`channel_overrides["endpoint"]`).

## Запуск

```bash
export AIGATE_AGENT_GATEWAY_URL=http://aigate.internal:8080
export AIGATE_AGENT_CHANNEL_KEY=<ключ канала>
python -m agent.main
```

Linux требует `xclip`, `xsel` или `wl-clipboard`; macOS и Windows работают
из коробки (pbpaste/pbcopy, PowerShell).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AIGATE_AGENT_GATEWAY_URL` | `http://localhost:8080` | адрес шлюза |
| `AIGATE_AGENT_CHANNEL_KEY` | — | ключ канала (X-AIGate-Key) |
| `AIGATE_AGENT_USER` | `$USER` | идентификатор для аудита |
| `AIGATE_AGENT_POLL_INTERVAL` | `0.5` | период опроса буфера, сек |
| `AIGATE_AGENT_FAIL_CLOSED` | `true` | очищать буфер при недоступном шлюзе |
| `AIGATE_AGENT_RESTORE_ENABLED` | `true` | детокенизация скопированных ответов |

Корпоративный деплой: автозапуск через systemd user unit / launchd /
планировщик задач Windows, конфигурация через GPO/MDM.

## Локальные приложения с настраиваемым API (Cursor и др.)

Приложения, позволяющие сменить base URL OpenAI-совместимого API,
подключаются напрямую к egress-каналу шлюза — это полнее, чем перехват
буфера (закрывает и набранный вручную текст):

- **Cursor**: Settings → Models → OpenAI API → Base URL =
  `http://aigate.internal:8080/v1`, API Key = ключ канала.
- **Любой OpenAI SDK / LangChain / n8n**: `base_url` на шлюз.

Приложения без такой настройки (Claude Desktop) покрываются агентом
по буферу обмена; полный перехват их трафика — этап 2 (локальный
MITM-прокси с корпоративным CA либо MCP-слой, раздел Э3 ТЗ).

## Ограничения

- Перехватывается буфер обмена; текст, набранный в приложении вручную,
  агент не видит (для Cursor решается сменой base URL, см. выше).
- Polling с интервалом 0.5 с: теоретически возможна вставка быстрее
  одного цикла; интервал настраивается.
- Детокенизация работает, пока жив маппинг сессии на шлюзе (TTL,
  по умолчанию 10 минут).
