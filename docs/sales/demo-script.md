# Скрипт демо AI-Gate (15 минут)

Цель: за 15 минут показать полный цикл «утечка → маскировка → аудит»
на реальном продукте. Все команды рабочие (проверены на этом репозитории).

## Подготовка (за день до демо)

```bash
git clone <репозиторий> && cd AI-Gateway
cp .env.example .env
# заполнить AIGATE_PROVIDER_API_KEY (или локальный Ollama, см. ниже)
# задать AIGATE_ADMIN_TOKEN=demo-admin
docker compose up -d          # либо: python -m gateway.main
curl -s localhost:8080/healthz   # {"status": "ok"}
```

Подготовить **демо-текст** (реалистичный, но синтетический — никогда не
использовать реальные данные клиента):

> Подготовь письмо клиенту. Клиент: Ержан Нурсултанулы, ИИН 900715300005,
> карта 4111 1111 1111 1111, задолженность: 1 250 000 тг.

И второй, с «секретом»:

> Почини конфиг: OPENAI_API_KEY=sk-proj-Ab12Cd34Ef56Gh78Ij90KlMnOp

Чек-лист: консоль `http://localhost:8080/admin` открывается; в
`localStorage` задан токен (`localStorage.setItem('aigate_admin_token','demo-admin')`);
терминал с крупным шрифтом; если демо браузерного канала — расширение
проверено на живом ChatGPT **в этот же день** (селекторы меняются).

## Ход демо

### 0:00 — Постановка (1 мин)

«Покажу три вещи: что уходит наружу вместо ваших данных, что видит
сотрудник и что вы покажете регулятору».

### 0:01 — Сценарий 1: маскировка и восстановление (5 мин)

Отправляем демо-текст через шлюз (канал приложений/RAG — так работает
любая ваша система, у которой сменили адрес API):

```bash
curl -s localhost:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "messages": [{"role": "user", "content": "Подготовь письмо клиенту. Клиент: Ержан Нурсултанулы, ИИН 900715300005, карта 4111 1111 1111 1111, задолженность: 1 250 000 тг."}]
}'
```

**Точка «вау» №1** — показать, что реально ушло провайдеру (dry-run):

```bash
curl -s localhost:8080/v1/check -H 'Content-Type: application/json' -d '{
  "text": "Клиент: Ержан Нурсултанулы, ИИН 900715300005, карта 4111 1111 1111 1111, задолженность: 1 250 000 тг",
  "dry_run": true}' | python3 -m json.tool
```

Проговорить вслух: *«Наружу ушло: Клиент [PERSON_1], ИИН [IIN_1], карта
[CARD_1], задолженность [AMOUNT_1]. Ни одного реального значения. А ответ
сотрудник получил уже с настоящими данными — ему ничего не мешает работать»*.

Дополнительно: «Детект ИИН — по контрольной сумме РК, а не "любые 12 цифр"»:

```bash
# случайное 12-значное число НЕ маскируется:
curl -s localhost:8080/v1/check -H 'Content-Type: application/json' \
  -d '{"text": "номер накладной 111111111111", "dry_run": true}'
```

### 0:06 — Сценарий 2: блокировка секрета (2 мин)

```bash
curl -s localhost:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "messages": [{"role": "user", "content": "Почини конфиг: OPENAI_API_KEY=sk-proj-Ab12Cd34Ef56Gh78Ij90KlMnOp"}]}'
# -> 403: запрос заблокирован политикой
```

Проговорить: *«API-ключ в промпте — это не "замаскировать", это инцидент:
запрос блокируется, событие в аудите, ключ пора ротировать»*.

### 0:08 — Сценарий 3: браузер (2 мин, если подготовлено)

Живой ChatGPT: вставить демо-текст → расширение перехватывает → в поле
ввода плейсхолдеры → ответ на экране с восстановленными данными.
Если расширение не проверено сегодня — пропустить сценарий, не рисковать.

### 0:10 — Консоль и аудит (4 мин)

Открыть `http://localhost:8080/admin`:

1. **Дашборд**: N запросов, M замаскировано, K блокировок,
   «0 утечек в открытом виде», «цепочка целая ✓».
2. **Журнал**: показать, что в записях **нет самих значений** — только
   типы и количества. *«Журнал сам не может стать источником утечки»*.
3. **Политика**: переключить SECRET block→mask на глазах у зрителей,
   повторить сценарий 2 — теперь ключ маскируется. *«Политику меняет ваш
   офицер безопасности, без перезапуска»*. Вернуть block.
4. Отчёт для регулятора:

```bash
curl -s localhost:8080/admin/api/report -H 'Authorization: Bearer demo-admin' | python3 -m json.tool
curl -s localhost:8080/admin/api/report.csv -H 'Authorization: Bearer demo-admin' | head -3
```

### 0:14 — Закрытие (1 мин)

*«Всё, что вы видели, работает в вашем периметре: docker compose up, день
на развёртывание. Предлагаем пилот на одном департаменте — через три месяца
у вас будет такой же отчёт, но по вашим реальным потокам»*.

Следующий шаг: дата скоуп-звонка + NDA.

## Вариант «данные не покидают периметр» (для госсектора / air-gapped)

Поднять Ollama локально и показать маршрутизацию чувствительных запросов
на локальную LLM (поле политики `sensitive_provider: "local"`):
чистые запросы идут во внешний LLM, запросы с ПДн — только в локальный.
Аргумент: «даже обезличенный текст может не покидать контур».

## Если что-то пошло не так

- Провайдер недоступен → показать fail-closed как фичу: «шлюз не знает,
  что с запросом, — значит, запрос не уходит. Это принцип продукта».
- Ложное срабатывание на демо → «порог настраивается политикой, на пилоте
  меряем false-positive rate на ваших текстах» (и показать detector-rules).
