# Качество распознавания

Как часто шлюз находит персональные данные и как часто ошибается. Цифры воспроизводятся одной командой:

```bash
python -I tools/eval_detection.py --misses
```

## Результат (23.10.2026)

Синтетический корпус: 500 офисных фраз и 18 «чистых» фраз без персональных данных (города, банки, госорганы, слова с заглавной буквы).

| Тип | Поймано | Всего | Полнота |
|---|---|---|---|
| ИИН/БИН | 58 | 58 | 100 % |
| ФИО, имя из словаря | 244 | 244 | 100 % |
| ФИО, имени нет в словаре | 252 | 256 | 98,4 % |
| Телефон | 105 | 105 | 100 % |
| Email | 110 | 110 | 100 % |
| Удостоверение/паспорт | 93 | 93 | 100 % |
| Дата рождения | 47 | 47 | 100 % |
| Адрес | 42 | 42 | 100 % |
| Госномер | 52 | 52 | 100 % |

Ложных срабатываний: 0.

**Как считается.** Сущность считается пойманной, только если её целиком закрывает одна находка того же типа. Если фамилия замаскирована, а имя ушло открытым текстом, это утечка, а не частичный успех. Ложное срабатывание — находка там, где персональных данных нет.

**Два пула имён.** Половина ФИО в корпусе собрана из имён, которых в словаре детектора нет («Бегайым», «Ростислав», «Злата»). Эта строка показывает, что будет с редким именем у реального клиента.

## Почему эти цифры оптимистичны

- Корпус синтетический, и шаблоны писал тот же разработчик, что и детекторы. У реальных документов больше форм: опечатки, ФИО строчными буквами, таблицы, смешение русского и казахского в одной фразе.
- У структурированных типов (телефон, email, ИИН, паспорт) 100 % объясняется тем, что их форматы известны заранее. Нестандартная запись телефона или адреса будет пропущена.
- Порог для пилота: клиент проверяет на своих документах, результат идёт в отчёт по пилоту ([шаблон](sales/pilot-report-template.md)).

## Известные пропуски

- **Неизвестное имя рядом с фамилией без типичного окончания**, например «Эмиль Сейткали». Слово «Сейткали» не похоже ни на имя из словаря, ни на фамилию по окончанию. Если рядом есть отчество или патроним («Сейткали Жансая Болатулы»), такая фамилия ловится.
- **Одно имя без фамилии** («Добрый день, Айгуль!») намеренно не маскируется. Само по себе имя редко идентифицирует человека, а его маскировка ломает смысл переписки.
- **ФИО строчными буквами** («айгуль ахметова») не ловится.
- **Даты** считаются датой рождения только рядом с контекстом («дата рождения», «г.р.», «туған күні»), остальные даты не трогаются.
- **Номер удостоверения РК** (9 цифр) ловится только рядом со словами «удостоверение», «уд. л.», «жеке куәлік». Паспорт РК (N + 8 цифр) ловится без контекста.

## Как устроен детект ФИО

1. Паттерны: русские отчества, казахские патронимы (-улы, -кызы, -тегі, латиница -uly, -kyzy), инициалы, контекстные слова («клиент:», «Mr»).
2. Словарь имён (казахские и русские, кириллица и латиница, падежные формы) и признаки фамилий по окончаниям: -ов/-ова, -ин, -енко, -ук, -бай, -бек, корейские фамилии.
3. Пара «явная фамилия + слово с заглавной буквы» принимается, если второе слово не название организации, не город и не служебное слово.
4. Найденный фрагмент расширяется на соседние части ФИО. Пересекающиеся находки объединяются: лучше замаскировать лишнее слово, чем выпустить половину ФИО.

Словарь — [`gateway/core/detectors/name_lexicon.py`](../gateway/core/detectors/name_lexicon.py), стоп-слова — [`names.py`](../gateway/core/detectors/names.py). Пополняются без изменения логики.
