# Облачный режим

Один шлюз обслуживает несколько компаний-клиентов. Подходит для офисов без собственного администратора: клиент получает ключи и пользуется чатом, расширением и обезличиванием файлов, а шлюз работает у оператора.

## Что изолировано

| | Общее для всех | У каждого клиента своё |
|---|---|---|
| Ключи провайдеров ИИ | да, принадлежат оператору | — |
| Политика (что маскировать, что блокировать) | — | `data/tenants/<id>/policy.json` |
| Журнал аудита и отчёт | — | `data/tenants/<id>/audit.log` |
| Свои правила (грифы, кодовые слова) | — | `data/tenants/<id>/detector_rules.json` |
| Хранилище меток (значения ПДн в памяти) | — | отдельное в памяти процесса |

Клиент определяется по ключу. По ключу одной компании нельзя прочитать журнал другой или восстановить её значения: тесты `tests/test_tenants.py` проверяют это явно.

## Ключи

| Ключ | Вид | Для чего |
|---|---|---|
| Ключ канала | `agk_<id>_…` | чат, расширение браузера, API, файлы |
| Админ-ключ клиента | `aga_<id>_…` | консоль `/admin`: политика, журнал, отчёт за месяц |
| Токен оператора | `AIGATE_OPERATOR_TOKEN` | операторский API: заводить клиентов, выдавать ключи |

В `data/tenants.json` хранятся только SHA-256 ключей. Ключ показывается один раз при выдаче: если его потеряли, выдайте новый и отзовите старые.

## Запуск

```bash
AIGATE_MULTI_TENANT=1
AIGATE_OPERATOR_TOKEN=<длинная случайная строка>
AIGATE_PROVIDER_API_KEY=<ключ OpenAI или другого провайдера>
python -m gateway.main
```

Требования к размещению:
- **Дата-центр в Казахстане.** Значения персональных данных живут только в памяти шлюза. Журналы и политики лежат на его диске. За рубеж уходит только текст с метками.
- **TLS на обратном прокси** (nginx, Caddy) перед шлюзом. Сам шлюз слушает HTTP.
- **Резервная копия каталога `data/`**: журналы аудита клиентов и реестр клиентов.
- **Один процесс.** Дневные лимиты и счётчики мест живут в памяти процесса. Места после перезапуска восстанавливаются из журнала.

## Операторский API

Все запросы — с заголовком `Authorization: Bearer <AIGATE_OPERATOR_TOKEN>`.

Завести клиента:

```bash
curl -s https://aigate.example.kz/operator/api/tenants \
  -H "Authorization: Bearer $OPERATOR" -H 'Content-Type: application/json' \
  -d '{"id":"too-alfa","name":"ТОО Альфа","seats":20}'
```

В ответе есть `admin_key` и `channel_key`. Их нужно передать клиенту, повторно их получить нельзя.

| Действие | Запрос |
|---|---|
| Список клиентов | `GET /operator/api/tenants` |
| Изменить мест, название, отключить | `PUT /operator/api/tenants/<id>` с `{"seats": 30}`, `{"enabled": false}` |
| Выдать ещё ключ канала | `POST /operator/api/tenants/<id>/keys` |
| Отозвать все ключи канала | `POST /operator/api/tenants/<id>/keys/revoke` |

Отключённый клиент получает 401 на всё, данные его не удаляются.

## Места

Место — это сотрудник, который пользовался шлюзом в текущем календарном месяце (по времени UTC+5). Когда места заняты, новый сотрудник получает понятный отказ, а те, кто уже работал в этом месяце, продолжают. Имя сотрудника берётся из поля «Ваше имя» в чате, из настройки расширения или из поля `user` в API.

## Что видит клиент

- `/chat` — рабочий ИИ-чат с ключом канала.
- `/admin` — консоль с админ-ключом: политика, журнал, отчёт за месяц для печати. Провайдеров ИИ клиент не меняет, ими управляет оператор.
- Расширение браузера: в настройках адрес шлюза и ключ канала. Администратор клиента может разослать их политикой браузера (GPO).
- `/try` — общая страница проверки. Она ничего не хранит и работает с политикой по умолчанию, а не с политикой клиента.

## Чего пока нет

- Отчёт в Telegram отправляется только по журналу оператора. Клиент открывает свой отчёт в консоли.
- Оплаты и счетов нет: места меняются через операторский API.
- Входа сотрудников через Google или Microsoft нет: работа идёт по ключу канала. Это этап 2.
